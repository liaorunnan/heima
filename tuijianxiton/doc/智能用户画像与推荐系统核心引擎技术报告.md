# 智能用户画像与推荐系统核心引擎技术报告

## 1. 项目概述

本项目构建了一个基于 **LLM (大语言模型)** 与 **规则引擎 (Rule-based Engine)** 相结合的动态用户画像系统。该系统旨在通过分析用户与客服的非结构化对话历史，提取深层用户特征（如价格敏感度、决策风格、人生阶段等），并将其转化为结构化、可量化、具备时间衰减特性的用户画像，为后续的精准推荐提供核心数据支撑。

### 核心价值
*   **非结构化转结构化**：将自然语言对话转化为机器可读的标签。
*   **动态演进**：画像并非静态，而是随着时间推移和新交互的发生而动态更新（引入半衰期概念）。
*   **深层推理**：不仅提取显性需求（如“买水壶”），还通过冲突检测推理隐性特征（如“极致性价比追求者”）。

---

## 2. 系统架构设计

本系统采用分层架构设计，确保数据流、逻辑处理与存储分离。

### 2.1 架构图 (Mermaid)

***

```markdown
graph TD
    subgraph Data Layer [数据源层]
        Chat[Chat Logs (chat.json/DB)]
        TagLib[Tag Ontology (tag.json/DB)]
    end

    subgraph Perception Layer [感知提取层]
        Pre[预处理: 格式化对话]
        LLM[LLM Tagger (llm_tagger.py)]
        Prompt[Prompt Engineering]
    end

    subgraph Cognitive Layer [认知画像层 (UserPersonaSystem)]
        Normalize[语义归一化]
        Weight[权重对齐 & 置信度评分]
        Decay[时间衰减计算 (Time Decay)]
        Conflict[冲突检测 & 衍生推理]
    end

    subgraph Storage Layer [存储与应用层]
        Profile[最终画像 (User Profile)]
        RecSys[下游推荐引擎]
    end

    Chat --> Pre
    TagLib --> Prompt
    Pre --> LLM
    Prompt --> LLM
    LLM -->|原始标签 JSON| Normalize
    Normalize --> Weight
    Weight --> Decay
    Decay --> Conflict
    Conflict --> Profile
    Profile --> RecSys
```

### 2.2 模块划分

1.  **数据接入层 (Input)**: 负责加载原始对话数据 (`chat.json`) 和标签知识库 (`tag.json`)。
2.  **感知提取层 (Perception)**: 利用 LLM 的语义理解能力，根据标签库定义，从对话中提取初步标签。
3.  **认知画像层 (Cognition)**: 系统的核心大脑 (`user_persona.py`)。负责处理标签的时效性、权重计算、冲突解决和长期记忆构建。
4.  **调度层 (Orchestration)**: `main.py` 负责串联上述流程。

*   **闭环更新**：提取完成后，立即实例化 `UserPersonaSystem` 并调用 `update_persona`，实现从“原始数据”到“最终画像”的闭环。

### 3.2 基于知识库的 LLM 提取 (`llm_tagger.py`)

**作用**：利用大模型将自然语言映射到 `tag.json` 定义的标签体系中。

**原理**：
*   **RAG (检索增强生成) 初级形态**：将 `tag.json` 作为上下文（Context）注入到 System Prompt 中。LLM 不仅是基于训练数据，而是基于我们提供的“标签本体论”进行分类。
*   **JSON Mode**：强制模型输出 JSON 格式，便于程序解析。

**代码解析**：
```python
def extract_user_tags(chat_history: str, tag_library: List[Dict]) -> str:
    # 动态注入标签库：让 LLM "学习" 我们的标签定义
    tag_list_str = json.dumps(tag_library, ensure_ascii=False, indent=2)
    system_prompt = AI_TAG_PROMPT.format(TAG_LIST=tag_list_str)

    response = client.chat.completions.create(
        model=settings.model_name,
        messages=[...],

    )
```

### 3.3 标签定义与知识库 (`tag.json`)

**作用**：定义画像的维度。这不仅是数据文件，更是业务逻辑的体现。

**设计亮点**：
*   **证据链定义**：每个标签包含 `description`，其中明确了【定义】、【强证据】、【弱证据】、【反例】。这实际上是 Prompt 的一部分，指导 LLM 如何进行推理，极大提高了提取的准确率。
    *   *例如 "极致性价比"*：明确指出 "对比拼多多价格" 是强证据。

### 3.4 动态画像引擎 (`user_persona.py`)

这是本系统的**核心算法层**，解决了 LLM 输出不稳定和缺乏时间维度的问题。

#### A. 时间衰减 (Time Decay)
用户的兴趣和特征是随时间变化的。昨天的“急需”在今天可能已经解决。
**原理**：使用指数衰减函数 $N(t) = N_0 \cdot e^{-\lambda t}$。

```python
def _calculate_decay(self, last_update_ts: float, lambda_factor: float) -> float:
    # 距离上次更新的时间差（小时）
    hours_diff = (time.time() - last_update_ts) / 3600
    # 指数衰减：时间越久，保留的分数越少
    return math.exp(-lambda_factor * max(0, hours_diff))
```

#### B. 语义归一化 (Normalization)
解决 LLM 输出同义词的问题（如 "保守" 和 "风险厌恶" 应视为同一特征）。

```python
self.TAG_NORMALIZATION = {
    "保守主义": "low_risk_tolerance",
    "风险厌恶": "low_risk_tolerance", 
    # 将不同的自然语言标签映射到统一的系统内部 Key
}
```

#### C. 冲突检测与衍生推理 (Conflict Detection)
**作用**：识别复杂的用户心理模型。简单的标签叠加无法描述复杂的人性。
**逻辑**：如果用户既有“高价格敏感度”又有“高品质要求”，系统推断其为“极致性价比追求者 (Value Seeker)”。

```python
def _detect_conflicts(self, current_time: float):
    # 逻辑门判断：既要低价，又要高质量
    if has_high_price_sensitivity and has_high_quality_requirement:
        # 触发衍生标签逻辑
        self.global_traits["trait_derivative"]["values"].append({
            "value": "value_seeker",
            "reason": "同时具备高价格敏感度和高品质要求"
        })
```

#### D. 权重对齐 (Score Alignment)
将 LLM 给出的模糊置信度（Tier S/A/B）转化为数学计算所需的浮点数权重。

```python
self.TIER_MAP = {"Tier S": 1.0, "Tier A": 0.7, "Tier B": 0.4}
```

## 4. 数据库接入规划 (Future Roadmap)

当前系统使用 JSON 文件模拟存储。在生产环境中，需要接入关系型数据库（如 MySQL/PostgreSQL）和向量数据库。

### 4.1 ER 图设计思路

1.  **`users` 表**: 基础用户表。
2.  **`chat_logs` 表**: 存储历史对话（替代 `chat.json`）。
3.  **`tag_library` 表**: 存储标签定义（替代 `tag.json`）。
4.  **`user_traits` 表**: 存储用户的全局画像状态（替代 `user_persona.json` 的 global_traits 部分）。
    *   `user_id` (FK)
    *   `trait_key` (e.g., price_sensitivity)
    *   `trait_value` (e.g., high)
    *   `score` (当前分值)
    *   `last_updated_at` (时间戳，用于计算衰减)
5.  **`user_intents` 表**: 存储品类意图。

### 4.2 接入步骤

1.  **数据加载改造 (`main.py`)**:
    *   将 `json.load()` 替换为 SQL 查询语句（如 `SELECT * FROM chat_logs WHERE user_id = ...`）。
2.  **持久化改造 (`user_persona.py`)**:
    *   在 `update_persona` 方法结束时，不再写入 JSON，而是执行 `UPSERT` (Update or Insert) SQL 语句，将最新的 Score 和 Time 更新到数据库。
3.  **读写分离**:
    *   **写路径**: 实时对话 -> 消息队列 -> 异步触发 LLM 提取 -> 更新数据库。
    *   **读路径**: 推荐服务 -> 查询数据库 -> 获取当前高分标签 -> 生成推荐列表。

## 5. 总结

本系统不仅仅是一个简单的标签提取器，而是一个具备**记忆**、**遗忘**和**推理**能力的认知引擎。

1.  **记忆**：通过数据库/JSON 持久化保存用户特征。
2.  **遗忘**：通过 `_calculate_decay` 算法，让陈旧的信息权重降低。
3.  **推理**：通过 `_detect_conflicts` 和 LLM，从表象行为推断深层心理（如从“问价格”推断“价格敏感”）。

这套架构能够有效支持下游的**个性化推荐**、**话术生成**以及**精准营销**场景。
