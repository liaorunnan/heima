# 第二次画像系统改进总结

本次改进针对《第二次修改错误.md》中提出的致命逻辑漏洞（多意图混淆）及工程化落地的不足进行了全面升级。

## 1. 核心改进点 (Core Improvements)

### 1.1 多品类意图拆解 (Multi-Intent Splitting)
- **改进前**：所有标签强行挂载在一个主类目下，导致“水壶的材质”被归为“摄像头的属性”，引发推荐混乱。
- **改进后**：LLM 现在能够识别对话中的多个品类（如 `baby_monitor` 和 `thermo_pot`），并分别为其生成 `category_intents`。
- **价值**：确保推荐引擎能够精准匹配特定类目的商品属性，解决“316不锈钢摄像头”类的逻辑错误。

### 1.2 全局特质与局部意图分离
- **结构化存储**：
  - `global_traits`：存储用户身份（二胎宝妈）、消费性格（砍价高手）等通用属性。
  - `category_intents`：存储针对特定商品的即时需求（如水壶是否除氯）。
- **衰减策略差异化**：全局特质采用低衰减率（长效记忆），品类意图采用高衰减率（即时意图），符合长短期兴趣分离理论。

### 1.3 工程化标准取值 (Engineering Ready)
- **枚举值映射**：要求 LLM 输出标准 snake_case 词汇（如 `second_child_mom`）而非文学化描述（如“配方还原论者”）。
- **标识符替换**：使用 `tag_code` 代替容易产生幻觉的 `tag_id`，入库时由后端统一映射。
- **价值**：数据直接可用于 SQL 查询和特征工程，无需二次清洗。

### 1.4 运营指令提取 (Actionable Insights)
- **指令标记**：引入 `is_instruction` 字段，识别“发顺丰”、“写贺卡”等即时服务指令。
- **价值**：画像数据不再只是被动存储，而是可以触发下游订单系统的自动化操作。

## 2. 提示词防过拟合优化 (Anti-Overfitting)
- **通用化示例**：将 Prompt 中的 Example 替换为完全无关的品类（连衣裙、猫粮），确保模型学习的是**分类逻辑**而非**特定商品知识**。
- **强化推理规则**：明确要求模型根据证据挖掘进行多意图判断，而非简单套用模板。

## 3. 运行验证结果
通过对测试聊天记录的分析，系统成功生成了包含两个独立品类意图的画像：
- **全局**：识别出 `second_child_mom` 身份。
- **意图 A (baby_monitor)**：关注 `cry_detection` (哭声检测) 和 `high_security` (安全加密)。
- **意图 B (thermo_pot)**：关注 `316_stainless_steel` (材质) 和 `dechlorination` (除氯)。
- **指令**：成功提取出 `sf_express` (发顺丰) 的物流指令。
